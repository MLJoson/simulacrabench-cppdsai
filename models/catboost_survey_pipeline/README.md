# Schema-driven CatBoost pipeline (Parquet input)

This project trains a separate CatBoost **classifier** for every schema item marked `PREDICT`, using **only** columns marked `GIVEN` as model features. The three datasets are trained independently.

## 1. Project layout

```text
catboost_survey_pipeline/
├── config.json
├── requirements.txt
├── schemas/
│   ├── unhcr_schema.json
│   ├── unicef_schema.json
│   └── world_bank_schema.json
├── data/
│   ├── unhcr_respondents.parquet
│   ├── unicef_respondents.parquet
│   └── world_bank_respondents.parquet
├── src/
│   ├── common.py
│   ├── train.py
│   └── predict.py
└── artifacts/                 # generated by training
```

The JSON schemas are included. Put the three Parquet files in `data/` with the exact filenames above, or edit their paths in `config.json`.

## 2. Install

Python 3.10+ is recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

`pyarrow` is the Parquet engine; the pipeline reads `.parquet` files directly using `pandas.read_parquet`.

## 3. Train all three datasets

Run from the project root:

```bash
python src/train.py --dataset all
```

Or train one dataset:

```bash
python src/train.py --dataset unhcr
python src/train.py --dataset unicef
python src/train.py --dataset world_bank
```

## 4. Outputs

For each dataset, the pipeline creates:

```text
artifacts/<dataset>/
├── models/
│   ├── <target-question-column>.cbm
│   └── ...
└── reports/
    ├── target_metrics.csv
    ├── gate_audit.csv
    ├── skipped_targets.csv
    ├── row_splits.csv
    ├── run_summary.json
    ├── <target>_classification_report.csv
    └── <target>_confusion_matrix.csv
```

`target_metrics.csv` includes accuracy, macro F1, weighted F1, macro precision/recall, row counts, and counts of dev/test labels not seen during training. Unseen-label rows are not scored because a classifier cannot predict a class it never saw during fitting.

## 5. Split behavior — important

The schemas specify the number of train/dev/test rows, but do not specify row-level assignments. The pipeline therefore creates a reproducible random assignment with seed `42`, matching the exact counts in each schema. One split assignment is shared across all targets within a dataset.

If you have an authoritative row-level split assignment from the data-generation process, replace `make_splits()` in `src/common.py` with that assignment. Do not claim that the random split reproduces an original split unless you have its row-level labels.

## 6. Gated questions

For a target with a schema `gate`, rows whose target value is null or exactly `NA_GATED` are excluded from that target's training/evaluation. Substantive responses such as "Don't know" and "Prefer not to answer" remain valid labels.

`gate_audit.csv` compares eligibility inferred from the gate parent and `observed_if` values with whether the target was actually observed. It reports mismatches rather than silently rewriting the data. This is especially important for UNHCR, whose schema notes that some inferred routing rules may not perfectly match observed records.

At prediction time, a gated target is routed using its parent. If the parent is another `PREDICT` item, the parent model is called first. Parent predictions are used **only to decide applicability**, never as model features. If a target is not applicable, output is `NA_GATED`.

## 7. Predict from GIVEN answers

Create a JSON file containing the answers to the GIVEN columns for one respondent. Example shape:

```json
{
  "Country": "Kenya",
  "Q01": "Example response",
  "Q02": "Example response"
}
```

The keys and response values must match the actual dataset/schema. Missing GIVEN answers are represented internally as `__MISSING__`.

Run:

```bash
python src/predict.py --dataset unicef --answers one_respondent.json --output predictions.json
```

The output contains one result per PREDICT target, including prediction, confidence (maximum class probability), and status.

## 8. Modeling notes / limitations

- Every PREDICT target is modeled as a classification problem. This is appropriate for categorical survey answers. If a PREDICT column is genuinely continuous (many distinct numeric values), it may need a CatBoost regressor instead; inspect target cardinality before treating it as classification.
- All GIVEN columns are treated as categorical strings. This is a safe baseline for mixed survey schemas and avoids accidental ordinal encoding. If some GIVEN columns are truly continuous numeric measures, consider a later mixed numeric/categorical preprocessing refinement.
- `auto_class_weights="Balanced"` is enabled by default. Compare with no class weights using validation macro F1 before finalizing.
- A model is skipped when it has fewer than two training classes. See `skipped_targets.csv`.
- Random row splitting may not be appropriate if observations are clustered, repeated, or time-ordered. The UNHCR schema describes independent cross-sectional rounds; if the goal is generalization to a later round/country, design a group/time-based holdout instead.
- The World Bank data includes post-assessment/tracer outcomes. This pipeline predicts them from GIVEN columns only; predictive associations are not causal effects.
- Check consent, data minimization, and governance requirements before using predictions for decisions affecting individuals.

## 9. Recommended next validation

Before interpreting the models, inspect:
1. `gate_audit.csv` for routing discrepancies.
2. `skipped_targets.csv` for targets with insufficient training examples.
3. `target_metrics.csv` for low macro F1 and severe class imbalance.
4. Confusion matrices for systematic class errors.
5. Whether the random split is suitable for your intended deployment setting.
